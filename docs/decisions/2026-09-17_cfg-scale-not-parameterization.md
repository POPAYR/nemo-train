# CFG scale 不可照搬 XNeMo,但原因不是 v-pred vs eps-pred

日期:2026-09-17
状态:已定 —— 交付/渲染默认 cfg=1.5

## 背景

我们的解码器是 rectified flow(v = ε - x0),XNeMo 官方是 eps-pred DDPM,官方推理用 cfg=2.5。
直觉上"参数化不同 ⇒ 适合的 cfg scale 不同",据此不照搬 2.5。**结论对,理由错。**

## 被否决的理由:参数化本身

v 空间与 ε 空间的 CFG 是**严格等价**的,同一个 w 给出逐点相同的引导方向。

设 `z_σ = (1-σ)x0 + σε`,`v = ε - x0`,可解出 `x0 = z - σv`,`ε = z + (1-σ)v`。
cond 与 uncond **共享同一个 z**(同一步、同一输入),仿射变换的偏移项在做差时消掉:

```
ε_cfg = z + (1-σ)·[v_u + w(v_c - v_u)]
      = [z + (1-σ)v_u] + w(1-σ)(v_c - v_u)
      = ε_u + w(ε_c - ε_u)
```

x0 空间同理:`x0_u + w(x0_c - x0_u)` 成立。
所以**在 v / ε / x0 任一空间施加同样的 w,结果相同**,参数化不改变 CFG 的有效强度。

## 真正让最优 w 不同的四条

1. **uncond 的定义不同(最大的一条)**。XNeMo 的无条件分支是三重置空
   (bank 不注入 + CLIP 置零 + 参考帧 motion,见 `scripts/pose2vid_xnemo.py`),
   我们是训练期 `cfg_drop=0.1` 的随机丢弃。`Δ = pred_c - pred_u` 的方向与模长不是同一个量,
   w 自然不可比。历史教训:曾因"只换 motion"这一处没对齐,长期误判 flow 不如 DDPM。
2. **σ 分布不同**。我们 uniform + `shift=3.0`,XNeMo 用 DDPM schedule。
   CFG 在高噪段对结构/布局的影响远大于低噪段,同一个 w 在两种分布下
   "停留在高噪段的时间"不同,沿轨迹的累积效应不同。
3. **求解器与步数不同**,20 步 flow 与 DDIM 的误差累积方式不一样。
4. **公式约定**。`cond + w·Δ` 比 `uncond + w·Δ` 整整强 1.0(见 docs 中 CFG 约定一节),
   抄公式不换算就差一档。

## 结论

按我们自己的消融定档,不照搬官方数值。人眼评定 **cfg=1.5 最接近 GT**,
定为交付与渲染的默认档(cfg=2.5 实测闪烁更重,像"加了一层噪声在闪")。
